# 大模型原理 2 分钟讲稿（面试用 · 2026-10-08）

> 目标：FDE/Agent 开发面试被问到 Transformer / 训练流程时，能讲满 2 分钟，且追问不倒。
> 方式：每个概念先一句人话，再给比喻，再给面试官追问的应对。全程不背公式。

---

## 一、2 分钟讲稿正文（面试直接念/背）

> 面试官，我用一句话框架讲：**大模型 = 一个会预测下一个词的"超强联想机器"，后面所有技术都是为了让它的联想"更准、更听话、更安全"。**
>
> 底层是 Transformer，它的核心机制叫**注意力（Attention）**。打个比方：读一句话时，人会自动把注意力放到重要的词上——"小明把球传给小红，**她**接住了"，"她"指的是小红，不是小明。注意力机制做的就是这件事：让每个词在看上下文的时候，知道该"重点看谁"。它跟传统 RNN 最大的区别是：**不是按顺序一个词一个词地读，而是整句话同时看**，所以能并行计算，也能处理很长的上下文。
>
> 预训练（Pretraining）就是用海量互联网文本，训练模型做"预测下一个词"这个任务，学出来的是"常识和语言能力"。
>
> 但光会预测下一个词还不够——模型会胡说、会不听话。所以有 **Post-Training（后训练）**，分两步：
>
> 第一步 **SFT（监督微调）**：拿人工写好的"高质量问答对"教模型模仿——这是让模型学会"好好回答问题"的格式和风格。
>
> 第二步 **对齐（Alignment）**：让模型的回答符合人类的偏好。传统做法是 **RLHF**：先训练一个"奖励模型"当裁判，给模型的回答打分（好的加分坏的扣分），再用强化学习（PPO）让模型顺着裁判的意思调整——就像教练给运动员录像打分，运动员按分数调整动作。**DPO** 是 2023 年的简化版：不训练裁判了，直接用"人类偏好对比数据"让模型自己学会"人类更喜欢哪种回答"，省掉了一整套强化学习流程，又稳又好用。
>
> 一句话收尾：**预训练给能力，SFT 给格式，RLHF/DPO 给偏好，评估保证质量**——这就是我理解的大模型训练全景。

## 二、概念卡片（每个：人话 + 比喻 + 追问应对）

### Transformer
- **人话**：能并行处理文本的神经网络结构，核心是注意力机制。
- **比喻**：一群人在看同一句话，每个人都能看到所有人的想法（并行），并且自动知道谁重要（注意力）。
- **追问"多头注意力"**：多组"注意力"同时从不同角度看（语法角度、指代角度、情感角度），最后合并——像多个专家各看一面再汇总。
- **追问"位置编码"**：并行处理会丢失"先后顺序"，所以给每个词加一个位置编号，模型才知道谁先谁后。

### 预训练 Pretraining
- **人话**：在海量文本上做"预测下一个词"，学出语言能力和世界常识。
- **比喻**：像婴儿泡在语言环境里，听多了自然就会说话。
- **追问"下一个词预测怎么学到知识"**：为了预测准确，模型被迫记住大量统计规律和事实（哪些词常一起出现、什么问题配什么答案），知识就藏在参数里。

### SFT 监督微调
- **人话**：用人工标注的高质量"问题→回答"对，教模型模仿。
- **比喻**：实习生在岗前培训——看老员工的标准答卷，照样子做。
- **追问"和预训练区别"**：预训练学"广泛能力"，SFT 学"特定格式与风格"；预训练数据是万亿级自动收集，SFT 数据是少量人工精标。

### RLHF
- **人话**：训练一个奖励模型当裁判打分，再用强化学习（PPO）让模型按分数调整回答。
- **比喻**：教练（奖励模型）给运动员（LLM）录像（生成回答）打分，运动员按分数改动作（参数更新），多轮下来动作越来越好。
- **追问"为什么需要强化学习而不是继续 SFT"**：SFT 只能学"人类给的样本"，RLHF 能探索样本之外的更好回答；而且"好不好"本身就是主观的，奖励模型可以连续打分而不是只有对/错。
- **追问"PPO 是什么"**：一种稳定更新策略的强化学习算法，防止模型被一次坏梯度带偏——公式不重要，知道它是"RLHF 用的具体算法"就行。

### DPO
- **人话**：RLHF 的简化版——不训练裁判，直接用"人类偏好对比"数据让模型自己学会。
- **比喻**：不请教练录像打分了，直接拿"大家公认的好答案 vs 坏答案"给运动员看，让他自己悟出好坏标准。
- **追问"为什么比 RLHF 好"**：省掉训练奖励模型+PPO 的一整套流程，训练更稳、成本更低、更容易复现——2024 年后开源社区主流。

### Post-Training（面试高频词）
- **人话**：预训练之后的所有训练阶段的统称 = SFT + 对齐（RLHF/DPO）+ 评估迭代。
- **为什么面试官爱问**：因为预训练门槛（算力/数据）普通人碰不到，而 Post-Training 是中小团队真正在做的——对齐、微调、评测全在这层。
- **你的差异化**：你做过"评估"（一致性评估 std 0.00）——正好可以对上"Post-Training 之后必须有评估闭环"这个点。

## 三、可能追问的"延伸关"

| 追问 | 应对 |
|---|---|
| "LoRA 是什么？" | 冻结原模型参数，只训练一个小矩阵（低秩分解）——省显存、省时间，效果接近全量微调。比喻：不改整本字典，只在旁边贴一页笔记。 |
| "你知道 MCP 吗？" | 我手写过 MCP server（JSON-RPC 2.0）——工具接入的统一协议，让模型能调外部工具。 |
| "Agent 和微调什么关系？" | Agent 靠"上下文+工具"扩展能力（不训练），微调改模型本身（训练）；两者互补。 |
| "什么是幻觉？怎么缓解？" | 模型编造事实。缓解：RAG（检索增强，先查资料再回答）、工具调用（不确定就查）、评估（测幻觉率）。 |
| "上下文窗口不够怎么办？" | 截断/摘要/向量检索（RAG 最常用）——你的 RAG 项目就是回答。 |
