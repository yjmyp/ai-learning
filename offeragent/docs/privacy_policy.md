# 隐私政策与用户协议（草案 v1 · 2026-10-08）

> **这份是草案，不是法律意见。** 在正式对外提供服务前，请按你的实际部署主体
> （个人 / 公司）、部署地区、面向人群，找法务或按《个人信息保护法》要求逐条核对，
> 补上运营者名称与联系方式。下面每一条都对应代码里真实的行为，不是套模板。

## 一、我们收集什么、为什么

| 你提供的内容 | 用途 | 是否必需 |
| --- | --- | --- |
| 简历、教育背景、项目经历、技能 | 生成个人画像、匹配岗位、生成话术、准备面试 | 必需（不提供就无法使用核心功能） |
| 自我蒸馏问答的回答 | 生成画像与偏好，用于岗位筛选与匹配打分 | 可选（不答则画像不完整） |
| 岗位链接 / 岗位描述 | 分析 JD、算匹配度 | 使用该功能时必需 |
| 投递记录、复盘记录 | 记录进展、生成复盘、改进画像 | 可选 |
| 照片（可选） | 简历打印版与名片页头像 | 可选 |

**我们不收集**：身份证号、银行卡、生物特征、通讯录、位置轨迹、设备通讯记录。

## 二、数据存在哪、发给谁

1. **本地优先**：上述内容默认只写入运行本应用的机器的 `offeragent/data/` 目录，
   不会上传到开发者服务器。你自己部署 = 数据在你自己的机器上。
2. **调用模型时**：生成画像、打分、写话术、面试拷问等功能会把**相关文本片段**
   发送给模型服务商（默认 DeepSeek API）进行处理。请遵守该服务商的条款与数据政策；
   不想发就别点这些按钮。
3. **抓岗位时**：应用会访问公开招聘页面（如实习僧、牛客等）读取公开信息，
   只读、低频、不模拟登录批量操作。
4. **不做的事**：不向第三方出售、出租、交换你的个人信息；不把你的简历用于训练模型。

## 三、你的权利（都做成了按钮，不用发邮件）

| 权利 | 在哪做 |
| --- | --- |
| 知情：知道有哪些数据、占多少 | 设置 → 隐私与数据（显示文件数与体积） |
| 导出 / 携带 | 设置 → 隐私与数据 → 📦 打包我的全部数据（zip） |
| 删除 | 设置 → 隐私与数据 → 🗑️ 删除我的全部数据（输入「删除」确认） |
| 更正 | 简历、画像、岗位库都可以直接编辑后覆盖保存 |

清空会删除简历、画像、岗位库、投递与复盘记录；保留本机配置文件
（API Key、界面主题、每日目标），这些不是你的求职数据。

## 四、保留期限

- 数据保留到**你主动删除为止**（本地存储，没有自动过期策略）。
- RAG 服务的运行日志（`rag2/data/trace.jsonl`）记录问答的耗时、成本、引用来源，
  单文件超过 5MB 自动轮转，只保留最近一份备份，其中不含简历原文。

## 五、安全措施（做了什么）

- API Key 只存本机配置或部署平台 Secrets，**不写进代码**（有自动化测试守着这条，
  见 `test_repo_hygiene.py`）。
- 求职数据目录 `offeragent/data/` **不纳入版本控制**（不会随代码公开）。
- 公开部署时可设访问密码（哈希存储，不存明文）。
- RAG 服务：写操作需 API Key、按客户端限流、错误信息不回传堆栈。

**做不到的（如实说）**：当前版本是单实例共享一份数据目录，**没有多用户隔离**。
也就是说，如果你把它部署成公开链接给多个人用，大家共用同一份数据。
给陌生人用之前必须先做账号体系与数据隔离——这条是硬约束，不是建议。

## 六、用户协议要点

1. 本工具提供的是**信息整理与草稿辅助**，不承诺任何岗位结果、面试通过率或录用结果。
2. 生成内容（画像、话术、简历描述）**由你负责核对后再使用**；请勿填入不实信息。
3. 你需要对自己提交到第三方面试/招聘平台的内容负责；应用内所有投递动作
   **最后一步永远由你本人点击**，不提供自动群发。
4. 不得用本工具抓取非公开数据、绕过平台风控、批量打扰招聘方。
5. 服务按"现状"提供，本地部署的数据丢失风险由使用者自行承担，建议定期用
   设置页的导出功能做备份。
