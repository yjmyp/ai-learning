# 生产级 / 商业化就绪度评估（2026-10-08）

> 这份文件回答两个问题：**两个项目离"生产级"还差什么、离"商业化"还差多少。**
> 判定原则：只写能拿命令或数字验证的结论，不写"已经很好"这种无法证伪的话。

## 一、判定标准（先说尺子，再说分数）

一个软件要算"生产级"，业内看这几条。左边是标准，右边是本项目的现状。

| 维度 | 生产级标准 | 现在到什么程度 |
| --- | --- | --- |
| 可部署 | 一条命令起服务、配置走环境变量、数据持久化 | ✅ 有 Dockerfile + compose，配置全走 env，data 挂 volume |
| 可观测 | 有请求 ID、延迟分位、错误率、成本 | ✅ RAG 有 JSONL trace（P50/P95/拒答率/单次成本）+ `X-Request-ID` |
| 可守卫 | 鉴权、限流、结构化错误、探针分工 | ✅ 13 项验收通过（401/422/429/503/探针不占额度） |
| 可验证 | 有评估集、有回归测试、有 CI | ✅ RAG 54 条评估集 + `run_tests.py` 18 通过 / 0 失败；⬜ CI 刚加，需跑过一次绿 |
| 可扩容 | 压测出容量、瓶颈定位、扩容路径 | ✅ 有压测报告（冷启动 15.3s / 稳态 66ms / 饱和 ~22 QPS） |
| 安全合规 | 密钥不进代码、隐私数据边界清晰、用户可导出/可删除 | ✅ 密钥门禁测试 + 设置页「隐私与数据」（导出 zip / 一键清空，带路径护栏）；⬜ 隐私政策/用户协议正式文本仍未落成页面 |
| 多租户 | 用户之间的数据互不可见 | ❌ 没有。现在单实例共享一份 data/，只靠一个访问密码 |
| 输入防护 | 参数校验、日志不无限增长 | ✅ RAG 服务：问题长度 ≤2000、top_k ≤50（超限 422）；trace JSONL 到 5MB 自动轮转 |

## 二、两个项目的现状（逐项带证据）

### RAG v3 检索服务

| 能力 | 证据 |
| --- | --- |
| 存活/就绪探针分工 | `GET /live` 秒回不碰模型；`GET /ready` 索引空返回 503 |
| 启动预热 | `SERVICE_WARMUP=1` 后台预热，实测首请求 **15333ms → 62ms** |
| 限流 + 探针不占额度 | `SERVICE_RATE_LIMIT/WINDOW`；`test_service_prod.py` 13/13 |
| 结构化错误 | 401 / 422(bad_mode) / 429(rate_limited + Retry-After) / 500 统一 JSON + request_id |
| 容量数据 | `rag2/eval/loadtest_report.md`：并发 1→66ms P50，并发 8→22.6 QPS / 388ms P95 |
| 资料目录可配置 | `RAG2_DOCS_DIRS`（宿主/容器挂载不同路径不用改代码） |

**已知瓶颈（写清楚，被问才不慌）**：向量推理在服务进程内，单进程 CPU 饱和约 20-22 QPS；
扩容要么多 worker（每 worker 一份模型，内存 ×N），要么把 embedding 抽成独立服务做 batch，要么加查询缓存。

## 三、离商业化还差什么（按阻塞强度排序）

### 🔴 硬阻塞（不做就上不了线给陌生人用）

1. **多用户数据隔离**：现在所有用户共享 `offeragent/data/`（简历、画像、投递记录）。
   要商业化必须做：账号体系 → 每用户独立目录或数据库行级隔离 → 权限校验。
   工作量：数据库化 + 登录（2-3 天），并要补一套"用户 A 看不到用户 B"的测试。
2. **隐私合规**：收集的是简历、个人画像（敏感个人信息）。
   已做：设置页「隐私与数据」——数据在哪、只在本机、导出 zip、一键清空（`privacy_tools.py`，
   带路径护栏 + 保留本机 config.json，验收 6/6）。
   还差：隐私政策与用户协议的正式文本（作为页面可点开）、留存期限说明。
   工作量：剩余约半天（纯文案与页面）。
3. **平台条款边界**：批量抓岗位/半自动投递要守平台 ToS。
   现在的红线设计（发送动作永远人点、低频只读、绝不自动群发）是对的，要在产品内写明并保留日志。

### 🟡 影响体验与口碑（能上但会被差评）

4. 岗位数据源稳定性：抓取依赖平台页面结构，平台改版就断 → 需要失败告警 + 多源冗余。
5. 结果可解释：用户要知道"为什么筛出这个岗位" → 结构化打分已给五维证据，仍需在 UI 上更直白。
6. 冷启动内容：新用户没有履历，画像质量差 → 需要引导式问答（已有 Self-Distill 15 题，可继续强化）。

### 🟢 规模化才需要

7. 监控告警（错误率/延迟/成本阈值）、灰度发布、备份恢复演练
8. 计费与配额（按次/按月）、发票
9. 内容审核（用户输入进入模型的风险）

## 四、客观结论：离商业化"程度"多少

- **作为"能演示、能讲清楚的技术作品"：100% 达标**（可部署、可观测、可验证、有容量数据）。
- **作为"给陌生人用的小工具"：约 75%**。用户能导出/清空自己的数据、密钥与隐私数据都有门禁；
  仍缺账号体系与多用户数据隔离（这两项决定了第二个陌生用户进来会不会看见第一个人的简历）。
- **作为"能赚钱的产品"：约 30%**。还缺付费闭环、数据源稳定性、真实的用户留存数据。

一句话：**技术上已经到"生产级"，产品上还停在"单人工具"。**
下一步的分水岭不是加功能，而是把"单人工具"变成"多人服务"。
