```markdown
## 怎么启动一个新任务
先找一个能跑的最小例子改，改着改着再回头看原理。不要一上来就让他从空白文件写新功能，那是最容易卡的地方。任务目标要先说清楚，目标不清楚时他容易停住。

## 怎么学新东西
看官方文档加抄改现成代码，然后做一个小 demo 验证。他没做过的技术包括 LangChain、Docker、模型微调、多 Agent，这些都要按这个路径来。他更擅长在现成代码上改，而不是从零起手。

## 什么条件下效率高
下午和晚上效率高，一个人安静时最好。任务类型上，把链路跑通这件事最顺，从读文件到检索到生成，能一块块拆开调。不要频繁催他，有人催时容易停住。

## 卡点特征（他卡住时是什么表现，别人怎么帮他最快）
卡住时先硬扛一会儿，扛不动就换别的任务缓一下，很少主动找人。他不太主动说话，所以别人要主动问。帮他最快的方式是给一个能跑的最小例子，或者把任务拆成一块块，让他先跑通链路再回头调原理。

## 协作偏好（分工方式、同步频率）
喜欢各做一块最后合，但自己一个人做也行。同步太频繁会打断他，所以不要高频同步。他看得懂别人的代码，所以合代码这块没问题。

## 决策依据
先列出来对比，实在分不清就问人。不是靠直觉，也不是直接问别人。

## 不能接受的工作方式
最不能接受目标是天天变、没人带又要我出结果的活。也不能接受长期高频催促。
```

```markdown
# 个人画像：余剑



## 一、基本信息

## 二、技能画像



**核心技术栈**

- **Python 工程**：独立完成完整脚本与项目（文件处理、API 调用、异常处理、模块拆分）

- **大模型 API**：DeepSeek 全链路调用（请求/响应、连续对话、超时与异常处理）

- **RAG 全链路**：文档解析 → 300 字/块切分（重叠 50）→ bge-small 向量化 → Chroma 向量库 → top-k 召回 → TF-IDF 重排 → 带引用生成

- **向量库**：Chroma（持久化、集合管理、余弦距离）

- **检索评估**：自建 12 条评估集，量化 top-1/3/5 命中率

- **Agent 工具调用**：JSON 协议工具调用 + 参数合同校验 + 错误回填自纠错循环

- **工程化**：FastAPI 基础、Streamlit 界面与 Streamlit Cloud 部署、Git 全流程

- **调试能力**：定位修复真实 bug（嵌套 JSON 正则截断、模块导入缺失、离线缓存联网卡死）



**技能结构特点**：以「AI 应用落地」为主线，具备从数据处理 → 检索 → 生成 → 部署 → 评估的完整链路能力，偏工程实现与系统集成，而非模型训练。



## 三、项目经历



**1. RAG 知识库问答系统（已上线）**

- 定位：个人知识库 → 检索增强问答，回答带引用溯源

- 数据：11 篇资料 → 254 块；top-1/3/5 = 75% / 83% / 92%

- 技术：Python / bge-small-zh-v1.5 / Chroma / FastAPI / Streamlit / DeepSeek API

- 已知不足：固定切分不语义感知、评估集仅 12 条、无拒答阈值



**2. Agent 工具调用 Demo**

- 定位：模型按 JSON 调用 add/subtract/multiply；参数校验守卫可挡 5 类坏输出（未知工具/缺参/类型错/非对象/非法 JSON）

- 技术：Python / Function Calling / JSON Schema 校验

- 已知不足：工具仅 3 个、无记忆、无多轮规划



**3. OfferAgent（进行中）**

- 定位：先蒸馏自己，再做岗位匹配的求职 Agent

- 差异化：市面产品直接做岗位匹配，本项目加入 Self-Distill（先认识自己）



## 四、求职目标



- **主投**：AI 应用开发实习（RAG / 大模型应用 / Agent）

- **次投**：大模型评测、懂技术的 AI 产品经理

- **不投**：纯算法 / 模型训练岗、内容岗（AIGC 视频 / 分镜 / 小说编辑）、与 AI 无关的后端岗



## 五、优势



1. **完整链路能力**：能独立跑通「数据 → 检索 → 生成 → 部署 → 评估」全流程，不是只会调 API 的碎片技能。

2. **数据说话的习惯**：习惯用「254 块 / 83%」这类量化指标描述成果，而非概念堆砌。

3. **真实工程 debug 经验**：有可讲述的线上 bug 修复记录（正则截断、导入缺失、缓存卡死），具备排查能力。

4. **自学与落地能力**：项目驱动自学，能从 0 到上线，具备独立交付意识。

5. **方向聚焦且差异化**：Agent 方向加入 Self-Distill 思路，体现产品思考与技术实现的结合。



## 六、不足



1. **评估体系薄弱**：RAG 评估集仅 12 条，统计置信度有限，缺乏更系统的评测方法。

2. **检索质量受限**：固定长度切分非语义感知，可能影响长文档语义完整性。

3. **Agent 能力偏浅**：工具仅 3 个，无记忆机制、无多轮规划，与生产级 Agent 有差距。

4. **缺乏拒答与安全机制**：RAG 系统未设拒答阈值，存在幻觉风险。

5. **缺少大规模/团队协作经验**：目前均为个人项目，未体现多人协作、代码评审、CI/CD 等工业流程经验。

6. **算法深度有限**：不做模型训练，对底层模型原理理解深度有限（与求职方向一致，非硬伤但需知晓边界）。
```
