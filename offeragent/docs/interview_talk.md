> 用途：把项目讲出深度，不是背功能列表。核心原则：**先讲问题，再讲方案，最后用数字证明**。
> 数据来源：run_tests 20/0、一致性评估 std 0.00、MCP selftest、LangGraph 真实跑通、production_readiness 8 维。

## 一、30 秒电梯陈述（开场用）

> "我做了一个求职 Agent：它先通过 4 轮问答把我自己蒸馏成结构化画像，然后联网抓岗位、用工具链评估质量、对比画像打匹配分（低于 60 分自动建议不投），通过门禁后自动生成真人风格话术并做禁用词自检，最后投递前自动核验链接、停在人工确认。整个流程用 LangGraph 图编排，每一步落 trace 可观测。我给它做了评估体系：同一岗位重复打分标准差从 3.31 降到 0.00。"

## 二、5 分钟自述框架（按主线讲）

1. **问题**：求职者不知道自己适不适合岗位、话术像机器人、投递容易踩空（链接失效/假岗）。
2. **方案**：Agent 化全链路——自我蒸馏（画像）→ 联网搜岗 → 工具链评估 → 匹配打分+门禁 → 话术生成+自检 → 链接核验+人工确认投递。
3. **工程化**：五层架构（页面/业务/基础/引擎/简历子系统）、单一权威源、状态与事件分离、注册表扩展。
4. **Agent 化**：工具注册表（10 工具）+ 参数守卫 + ReAct 循环 + 记忆（SQLite + 向量三档降级）+ Plan/Reflect 节点 + LangGraph 图编排版 + 手写 MCP server。
5. **评估与可观测**（分水岭，重点讲）：
   - 一致性评估：旧法（模型随口给分）标准差 3.31 → 结构化五维加权 0.00（同一输入永远同一分数）
   - 工具守卫 6/6、端到端 13 岗实测 62-88、多岗位泛化 78/72/88
   - 每步 trace 落盘 + agent_trace_view 可视化页
6. **生产就绪**：Dockerfile+compose（12/12 静态校验）、CI（GitHub Actions）、隐私合规（导出/清空/路径护栏 8/8）、production_readiness 8 维自评。

## 三、可深挖技术点（每个：一句话答案 + 追问应对）

### 1. 为什么用 meta.json 做单一权威源？
**一句话**：岗位的状态（待投/已投/面试中）、匹配分、来源 URL 全放 `.meta.json`，JD 原文放 `.txt`——改一个数字不用重写整篇 JD，且所有页面读同一份。
**追问"状态和事件分开"**：状态会覆盖（现在什么样），事件只追加（发生过什么）——`applications.jsonl` 是事件流，`meta.json` 是快照，两者配合可追溯。

### 2. 匹配打分怎么防"模型随口给分"？
**一句话**：用五维加权（硬技能 0.30/项目证据 0.25/地点 0.15/时间 0.15/门槛 0.15），本地规则计算，模型只做 JD 拆解。
**数字**：旧法同一岗位重复 5 次标准差 3.31，新法 0.00——换提示词/换模型不影响历史分数，所以能当投递决策依据、能做回归测试。

### 3. 为什么投递要"停在人确认"？
**一句话**：执行类动作（打开投递链接、标记已投）永远停在人确认——AI 可以分析、建议、生成，但"发送"这个动作的后果由人承担。
**追问**：这是 Nvidia OpenShell 的安全边界思路 + OpenAI 的 human-in-the-loop。工具分两级：规则工具免费直跑、LLM 工具调一次模型、执行工具必须人确认。

### 4. 手写 MCP server 是什么？
**一句话**：用 JSON-RPC 2.0 + stdio 实现了 MCP 协议子集（initialize / tools/list / tools/call），把 10 个工具暴露成任何 MCP 客户端（Claude/Cursor/Codex）都能挂的标准接口，带 humanConfirm 标注。
**为什么手写不装包**：为了讲清协议长什么样——协议就是"工具名+描述+inputSchema"，我的工具注册表本来是私有格式，加一层翻译就是 MCP。

### 5. LangGraph 版和自研引擎什么关系？
**一句话**：自研引擎（offer_agent_core）是 ReAct 循环（模型自主决定下一步），LangGraph 版（offer_agent_langgraph）把投递流程画成 StateGraph：9 个节点 + 2 条条件边（门禁 ≥60 才写话术、话术有禁用词自动重写 ≤3 次）。
**追问"为什么两套"**：自研版证明我懂循环原理（消息回填、预算防死循环、trace），LangGraph 版证明我懂框架（State/TypedDict/条件路由）——面试 JD 写"熟悉 LangGraph 底层原理"，两套都讲才立得住。

### 6. 怎么防止 Agent 乱调工具？
**一句话**：参数守卫（safe_call）——工具调用前对照注册表查：工具存在吗？参数齐吗？类型对吗？坏输出踢回去让模型重来。
**数字**：eval_agent 工具守卫 6/6、JSON 提取 6/6。

### 7. 记忆怎么做的？
**一句话**：两层——SQLite 存事实（键值，可增删纠错），memory_vec 存语义向量（bge 本地模型，三档自动降级：bge 向量 → TF-IDF → 词面重合），解决"上次那个高匹配的南京岗位"这种模糊指代。

### 8. 可观测怎么做？
**一句话**：每一步模型想了什么、调了什么工具、结果如何，都落 `agent_logs.jsonl`，页面层 agent_trace_view 展示运行次数/平均步数/工具分布/时间线——面试官能指着 trace 问"这步为什么失败"，我能当场答。
**追问"成本可观测"**：call_llm 返回 usage，trace 记录每轮 token 数，能算单次任务成本。

### 9. Docker 和生产就绪到什么程度？
**一句话**：Dockerfile + docker-compose（config 全走 env、data 挂 volume、健康检查 /_stcore/health），静态校验 12/12，CI 有 docker build job；production_readiness.md 按 8 维自评（可部署/可观测/可守卫/可验证/可扩容/安全合规/多租户/输入防护）。
**诚实交代**：多租户数据隔离还没做（单实例单密码），商业化前要补——面试官喜欢看到你知道边界。

### 10. Plan-and-Execute 和 Reflection 是什么？
**一句话**：Plan 节点先给 3-6 步显式计划（每步用哪个工具、要拿到什么），再执行——可解释、可中断；Reflect 节点收尾自评"目标达成没、证据够不够、下一步做什么"——不把模型最后一句当结论。

## 四、面试官可能的"为什么"杀招 + 应对

| 杀招 | 应对 |
|---|---|
| "这跟你直接调 API 有什么区别？" | 有闭环：模型能决定调哪个工具、根据结果继续，不是一次性问答；有安全边界和预算防死循环 |
| "评估 0.00 是不是因为规则太死？" | 承认：结构化打分牺牲了模型语义灵活性，换取可复现——所以保留模型报告做补充，分数+报告一起给 |
| "为什么用 Streamlit 不用 React？" | 实习阶段以最快出结果优先；FDE 岗要求前端的话我在补 Vue/React |
| "会不会被 AI 取代？" | 这个项目就是"AI 增强人"的实证：AI 干分析，人做决定 |
| "你最骄傲的代码是哪段？" | 一致性评估脚本（证明结构化 > 直觉）或 MCP server（手写协议）——选一个讲 2 分钟 |
