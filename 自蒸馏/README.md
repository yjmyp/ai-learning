# 自我数字人蒸馏 Agent（设计方案）

> 状态：设计完成，档案已建；Agent 代码排期 8/21 后（阶段 B，复用 rag2，预计 2-3 天出 MVP）
> 一句话：把"你"（简历、项目、知识、表达风格）蒸馏成一个 Agent——既能拷打你面试，也能代表你回答。

## 一、两个模式

### 模式 A：面试官模式（拷打自己）
- 输入：你的简历 + 目标 JD
- 行为：按 JD 生成高频问题 → 你回答 → 评估你的回答（逻辑/数字/深度/语气）→ 给改进意见
- 用途：投递前练 10 遍，把"项目拷打"练到脱稿

### 模式 B：数字分身模式（代表自己）
- 输入：任意问题（HR 问"介绍下自己"、面试官问"为什么选我们"）
- 行为：检索"个人数字档案"→ 以第一人称、你的风格生成回答 → 你修改后存回档案
- 用途：产出标准答案，沉淀成"面试题库+答案"

## 二、技术架构（复用 rag2）

```
个人数字档案.md（蒸馏源，唯一事实来源）
        ↓ 解析+切分+向量化（bge）
    Chroma 档案向量库（rag2 复用）
        ↓ 检索 top-k
  Agent 循环（ReAct）
    ├─ 工具1：retrieve_profile(问题) → 相关档案块
    ├─ 工具2：ask_question(JD) → 生成面试题
    ├─ 工具3：evaluate_answer(题目, 回答) → 评分+意见
    └─ 工具4：gen_answer(问题) → 第一人称回答（数字分身）
        ↓
    Streamlit 界面（两个模式切换）+ CLI 版
```

## 三、数据源（蒸馏什么）

1. `个人数字档案.md`（已建，核心）
2. 简历（`简历/余剑-简历-AI应用开发实习.md`）
3. CONTEXT.md（学习路径与特点）
4. 学习笔记（知识面）与进度日志（过程证据）
5. 阶段 A 产出的 10 个 Q&A（8/20 前写完，正好喂给 Agent）

## 五、注意（客观）

- 数字分身 ≠ 真人：它只能代表"档案里写了什么"，所以档案要持续维护（每次面试复盘都更新）
- 不造假：档案里"不会什么"也写清楚，面试被问倒时如实说比硬编强
- 这是加分项，不是主线；8/18 投递优先级永远高于它
