# 任务提示词模板（2026-10-08 从你我真实对话里提炼 + 优化）

> 用途：你下次给我派活时，照着这个模板写，我执行得更快、更少来回、交付质量更稳定。
> 这份文件是**从你实际用过的提示词**里总结的，不是凭空设计的。

## 二、优化的地方（差在哪）

| 你现在的写法 | 问题 | 改成 |
|---|---|---|
| "全做" | 我不知道做到什么程度算完，容易半成品堆仓库 | "全做，**每个改动都要有验证方式**（跑通/有数据/能演示）" |
| "弄得更美观" | 美丑没有判据，我会来回改 | "美观按 **X 参考**（截图/站点/规范），验收标准 = 三列/一页/配色统一" |
| "升级项目" | 升级到什么程度没说 → 我可能只做表面 | "升级到能**扛住面试 20 分钟追问**：每条改动能讲清为什么" |
| "看看有没有问题" | 范围太大，我给的意见会很泛 | "按 **这 4 层**逐层挑毛病：Planning/Memory/Tool/Reflection" |
| 一次给 5 个方向 | 我会铺开做，每块都浅 | "先做 **1 号**，做完给我看，再决定 2 号" |

## 三、任务卡模板（直接复制，填空即可）

```
【目标】一句话说清要什么结果（不是要什么过程）
【为什么】这件事要解决什么问题（让我能判断取舍）
【验收】怎么算完成？至少写一条可验证的（跑通 / 有数字 / 能演示 / 能讲清）
【边界】哪些不做、哪些必须问过你再做、哪些是红线
【参考】有没有对标物（项目 / 截图 / 文章 / 规范）
【产出】要文件、要命令、还是要我改代码？（默认：改代码 + 给验证方式）
【模型】默认 deepseek-flash，除非你明确说用别的
```

**填空示例（你上次那件事，用模板写会长这样）：**

```
【目标】把 RAG 项目升级成"可评估的检索服务"，OfferAgent 补齐 Agent 四层框架
【为什么】两个项目要能扛住面试深挖，也要能证明是我自己写的
【验收】① 每项都有测试脚本跑过 ② 关键指标前后对比（如 R@5）③ 面试文档同步
【边界】不加新功能、不动现有页面结构；密钥不落代码；发送类动作永远人点
【参考】GitHub 上 star 高的 RAG 项目（借架构不抄代码）
【产出】改代码 + 验证脚本 + 一页讲法
```

## 四、5 个高频任务的现成提示词（可直接粘）

**① 改 bug（最快的一类）**
```
现象：<报错原文或截图>
触发步骤：<做什么会复现>
期望：<应该怎样>
要求：先给根因证据（文件:行），再改；改完给我一条能复现验证的命令。
```

**② 加/改功能**
```
【目标】<一句话>
【验收】<怎么算完成，至少一条可验证>
【边界】不动 <某文件/某页面>；不改 <某逻辑>
要求：先给整体框架和改动清单，我确认后再写代码；写完跑测试给我看结果。
```

**③ 评估/挑毛病（你上次问"适不适合做面试项目"就是这类）**
```
对象：<项目/方案/简历>
用途：<投什么岗、给谁看>
要求：客观，不要偏向；按 <维度清单> 逐条打分给依据；先说结论再说理由；
      指出不能改的硬伤（学历/实习/笔试这类）和能补的缺口。
```

**④ 学代码（你要"讲清每一步在干什么"）**
```
文件：<路径>
我的基础：<会什么、不会什么>
要求：按执行顺序讲"为什么这么写"，每段给"如果删了会怎样"；
      最后出 3 个问题考我，我答完你判对错。
```

**⑤ 投递/求职（涉及外部动作）**
```
任务：<生成话术 / 筛岗 / 改简历>
红线：发送类动作我自己点，你只准备素材
验收：<能直接复制的成品 / 排好序的清单>
```

## 五、让我跑得更快更稳的 4 条硬约束（建议加进你的自定义指令）

1. **先查证据再下结论**：涉及数字、结论、兼容性时，先说"从哪看到的"，不要凭印象。
2. **不准交付半成品**：改完必须跑一次验证（测试/命令/页面）；跑不了就说清为什么跑不了。
3. **发现目标本身有问题就直接说**（比如"保证进大厂"不成立），并给可达到的替代目标。
4. **一次只推一件事到"完成"**：多任务时按价值排序，做完一个给一个证据，再开下一个。
