# OfferAgent 面试讲法（怎么讲不露怯）

> 用途：面试官问「这个项目怎么做的 / 为什么这么设计」时，从下面 8 个点里挑对应的讲。
> 原则：每个点都是项目里**真实实现**的东西，可以当场打开代码指给面试官看。宁可讲浅一层，不要编。

## 0. 三十秒电梯陈述（背熟）

> 「我做了个求职智能体：先通过 15 个问题把我自己蒸馏成一份结构化画像，然后对岗位库里的每个 JD 做匹配打分，低于 60 分自动拦下不建议投；通过的话生成投递话术，话术有 45 个禁用词做 AI 腔检测；投递前自动重访岗位链接，404 直接标记失效不让你投空。整个流程由一个 ReAct 循环驱动，模型自主决定调哪个工具，执行类动作必须停在人确认——最后那一下永远是人点的。」

## 1. 单一权威源：meta.json（被问「数据一致性」时讲）

**是什么**：岗位库每份 JD 旁边有个 `xxx.meta.json`，`match_score / status` 只存在这里；`agent_logs.jsonl` 只记事件（谁、何时、调了什么工具），历史分数是快照，不覆盖岗位库。

**为什么**：两个地方都存分数，改了一处漏了另一处，漏斗图就会和岗位库对不上。分两层后，统计只从一个地方算。

**一句话回答**：「数据只有一个权威源，日志只管记录不管状态，我用 `store.audit_scores()` 一键对账，Web 端数据页能看到对账结果。」

**可能被追问**：对账脚本怎么判断不一致？→ 以 meta.json 为准，日志里的分数只是当时的快照，不一致时以岗位库覆盖。为什么不全存数据库？→ 单机应用用文件更简单，不引入运维成本，且数据本来就是给人读的 markdown/json。

## 2. 投递防抖（被问「业务规则怎么落」时讲）

**是什么**：`store.check_apply_allowed` —— 已投的岗位禁止重复投递；24 小时内投过的也拦。

**为什么**：批量生成话术后最容易手滑重复投。防抖是纯函数、无副作用，可以单测。

**一句话**：「投递是低频但高代价的操作，我在数据层做了一层防重复校验：状态是'已投'的直接拒绝，24 小时内投过的给提示。规则写成纯函数，测试直接覆盖。」

## 3. 多 Agent 协作（被问「Agent 架构」时讲）

**是什么**：一个主管 Agent（Supervisor）是唯一能调工具的入口，下面挂三个子 Agent：岗位分析师（assess/split/match）、话术专家（generate/check）、投递复盘员（funnel/needs_followup）。每个子 Agent 有自己的状态和角色提示词。

**为什么**：单 Agent 把所有职责塞一个上下文，提示词互相污染（话术生成混进匹配逻辑）。拆开后每个角色上下文干净，而且**投递工具（open_application）不在任何子 Agent 的工具集里**——只有主管手里有，且标记 human_confirm。

**一句话**：「我用 Supervisor 模式拆了三个子 Agent，职责隔离；安全上有个关键设计——投递这个动作不在子 Agent 手里，主管调用也必须停在人确认。」

**可能被追问**：子 Agent 之间怎么传数据？→ 结果序列化回主管，主管决定下一跳。出错了怎么办？→ 话术截断会触发自纠错：错误信息回填给话术专家重试（有实测记录）。

## 4. 门禁机制 GATE_SCORE=60（被问「怎么控制质量」时讲）

**是什么**：`match_job` 返回 `verdict`（建议投 / 不建议投），低于 60 分自动提示别投空；日志带裁决列。

**为什么**：AI 生成的分数必须有个执行层面的闸门，不能"生成完就投"。门禁是硬规则不是软提示——代码里直接判。

**一句话**：「匹配分不是摆设，60 分以下是硬门禁：verdict 直接标'不建议投'，日志里每条都有裁决记录。这个阈值是参数，可以调。」

## 5. 链接失效检测（被问「工程细节」时讲）

**是什么**：`open_application` 执行前自动核验 URL——404/410 或域名不可达 → 拦截并提示"不要投空"；真实链接 200 放行。有实测：占位链接 404 被拦，真实链接放行。

**为什么**：岗位库是爬来的，链接会过期。投递前核验是成本极低的防呆（一次 HEAD/GET，6 秒超时）。

**一句话**：「投递前会先重访链接，失效的直接拦住——避免用户对着一个 404 的岗位准备半天话术。」

## 6. 记忆落盘 SQLite（被问「跨会话」时讲）

**是什么**：`agent_memory.py`，事实和对话写入 `data/memory.db`，跨会话记住用户（比如上次聊到的项目背景）。

**为什么**：无状态 Agent 每轮都像失忆，面试官问"你记得我之前说的吗"就尴尬。落盘后记忆是持久的。

**一句话**：「记忆层用 SQLite 持久化，会话之间不丢；测试和演示用纯内存模式，向后兼容。」

## 7. 话术禁用词 v6 + AI 腔检测（被问「生成质量」时讲）

**是什么**：45+ 个禁用词/短语（"很高兴""期待与您""赋能"这类 AI 腔），`check_talk` 生成后自动校验，命中就提示改写。

**为什么**：BOSS 直聘场景里 AI 味越重回复率越低。这是产品经验，不是技术炫技。

**一句话**：「话术生成完不是直接交付，会过一道禁用词校验，45+ 个 AI 腔词汇命中即拦截。这个清单是迭代出来的，v6 了。」

## 8. 数字分身 + 自我蒸馏（被问「差异化」时讲）

**是什么**：先问答式 15 题蒸馏出 `profile.md`（结构化画像），之后所有环节都用这份画像，不编造；公开名片页（`?twin=1` 免密）让 HR 直接问分身问题，提示词硬规则"没有就直说没有"。

**为什么**：市面上匹配工具直接拿 JD 匹配，没先"认识你"。先蒸馏再匹配，画像可复用、可演进（复盘写回画像）。

**一句话**：「差异化在 Self-Distill：先花 15 个问题把真实的我结构化，后面匹配、话术、分身全部基于这份画像——保证'只挑不编'，生成的内容全部来自真实素材。」

## 通用应答套路

- **被问「为什么用 X 不用 Y」**：先答 X 解决的实际问题（一个具体事故/痛点），再说 Y 的代价（复杂度/成本），最后说"如果规模上来，我会换 Y"——展示你有边界感。
- **被问「遇到过什么困难」**：用真实 debug 记录（切分稀释定义段、嵌套 JSON 正则截断、离线缓存卡死、云端 import 白屏），讲"现象 → 定位方法 → 修复 → 验证"四步。
- **被问「有什么缺点」**：主动说——评估集样本量小（12 条在扩）、岗位源依赖爬虫稳定性、单机文件存储不抗并发。诚实 + 给改进方向。
