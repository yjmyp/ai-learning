# 01 · RAG 知识库问答系统 — 深挖文档（面试主打项目）

> 本文档基于 `rag2/` 真实代码整理（2026-09-29 确认）。面试前反复读，直到每个问题能**用自己的话讲 2 分钟**。

---

## 一、项目一句话定位

**用检索增强生成（RAG）技术，实现"基于个人知识库的问答系统"：文档入库 → 向量化检索 → 混合召回 → 重排 → 带引用溯源生成回答，已上线可公开访问。**

面试开场 30 秒版：
> "我做了一个 RAG 知识库问答系统，核心是 5 层链路：文档解析切分 → embedding 向量化 → Chroma 向量库 → BM25+向量混合检索 + 重排 → 大模型带引用生成回答。检索质量量化到 top-3 命中率 83%，并且我自建评估集做 base/hybrid 对比，用数据驱动优化。"

---

## 二、系统架构（背这张图）

```
文档(.txt/.md/.pdf/.docx)
   │  loader.load_documents()
   ▼
chunker 段落贪心切分(300字/块, 50字重叠, 超长按句末标点切开)
   │
   ▼
embedder  bge-small-zh-v1.5 → 512维向量(本地离线缓存)
   │
   ▼
store  Chroma 持久化向量库(余弦距离, 集合管理)
   │
   ▼
retriever  ① 向量召回 top-20
           ② BM25 稀疏召回 top-20
           ③ minmax 归一化 + 0.7:0.3 加权融合
           ④ TF-IDF 字符n-gram 重排
           ⑤ 取 top-4
   │
   ▼
qa  DeepSeek-chat 生成回答(带引用编号)
   │
   ▼
app(Streamlit) / api(FastAPI)  —— 用户界面 + REST 接口
```

**模块文件**（面试官可能让你指）：loader / chunker / embedder / store / retriever / bm25 / reranker / qa / engine / config / eval_rag2

## 三、逐层技术要点（面试提问核心）

### 1. 切分策略（chunker.py）
- **为什么段落贪心**：按空行分段，段落实义较完整；把段落合并到接近 300 字，而不是机械按字数截断 → 保留语义完整性
- **重叠 50 字**：相邻块共享尾巴，避免"上下文刚好被切在边界"导致信息丢失
- **超长段落**（>300 字）：先按句末标点（。！？；）切，再对单句仍超长的硬切 → 尽量不切断语义单元
- **短板（主动讲）**：固定 300 字不是语义感知——语义上无关的内容可能被包进同一块，反之相关的被拆开。下一步：按标题/语义断点切分，或 embedding 检测断点

### 2. Embedding（embedder.py + config.py）
- **模型**：BAAI/bge-small-zh-v1.5，中文优化的小模型（~120MB），输出 512 维
- **为什么选它**：中文效果好 + 体积小（本地 CPU 可跑）+ 离线可用
- **离线优先设计**：`HF_HUB_OFFLINE=1`——本机已缓存模型，避免受限网络下 HuggingFace 下载卡死（**这是修过的真实 bug：Streamlit Cloud 和本机网络差异导致过联网卡死**）
- **面试延伸**：embedding 原理（把文本映射到语义空间，相似文本距离近）；bge 的对比学习训练；为什么中文要用中文模型

### 3. 向量库（store.py，Chroma）
- 持久化到本地 `data/chroma`；余弦距离作为相似度
- **为什么 Chroma**：轻量、本地持久化、API 简单，适合个人项目；生产用 Milvus/Weaviate/Qdrant
- **面试延伸**：余弦 vs 欧氏；HNSW 索引原理（图式近似最近邻）；为什么向量检索快（ANN 不是全量扫描）

### 4. 混合检索（retriever.py + bm25.py）⭐ 最值得讲
- **为什么混合**：向量检索懂语义（"怎么避免回答跑题"→ 相关），BM25 懂关键词（精确匹配术语、代码名、人名），两者互补
- **流程**：向量取 top-20 + BM25 取 top-20 → 合并候选集 → **minmax 归一化**（向量分和 BM25 分数量纲不同，必须各自归一化到 [0,1]）→ **加权融合**（`hybrid = 0.7×向量 + 0.3×BM25`，稠密为主稀疏为辅）→ 排序
- **归一化细节**（加分点）：`_minmax` 全相等时返回 0.5 避免除零——这是工程细节，能讲 = 你真的写过
- **评估对比**（eval_rag2.py）：同一评估集跑 `base`（纯向量）vs `hybrid`，看 top-1/3/5 变化——**用数据证明混合有效，而不是嘴上说**

### 5. 重排（reranker.py）
- **问题**：混合召回后，top-20 里相关块可能排名靠后
- **方案**：TF-IDF **字符 n-gram（2-3）** + char_wb 分析器，计算候选块与问题的词面相似度，重排取 top-4
- **为什么字符级不用词级**：中文分词依赖分词器，字符 n-gram 免分词、对中文/代码/术语鲁棒
- **短板（主动讲）**：这是**词面重排**不是语义重排；更强的方案是 cross-encoder（如 bge-reranker）或 LLM 重排，但更重。当前取舍：离线、轻量、够用

### 6. 评估（eval_rag2.py）⭐ 差异化核心
- **评估集**：12 条"问题 + 期望命中来源 + 关键词"，覆盖概念问答和 JD 调研类
- **命中判定**：返回块同时包含期望 source 且含关键词 → 命中
- **指标**：top-1/3/5 命中率（当前 base 与 hybrid 对比跑出 top-1/3/5）
- **为什么自建评估**：没有公开中文 RAG 评估集适配个人知识库场景；自建才能量化"每次改动是变好还是变坏"
- **短板（必须主动讲）**：12 条太少、命中判定粗糙（source+关键词，不是语义判定）、未覆盖拒答场景

### 7. 生成与溯源（qa.py + engine.py）
- 检索到的块拼进 Prompt → DeepSeek-chat 生成
- **带引用溯源**：每条回答附引用编号 + 来源定位，可一键查看原文 → 回答可验证，防幻觉
- **API key 多级查找**（config.py）：环境变量 → local_key.py → secrets.toml → st.secrets——兼顾本地与云端部署

## 四、修过的真实 bug（面试讲"踩坑"用，比项目本身更加分）

1. **联网卡死**：本机/云端网络差异导致 HuggingFace 下载模型超时卡死 → 加 `HF_HUB_OFFLINE` 离线优先 + 模型本地缓存
2. **离线缓存导致的联网卡死**：早期"先尝试联网再回退离线"的设计在受限网络下反而卡住 → 改为环境检测（`/mount/src` 存在=云端=允许联网）
3. **评估"看起来提升"陷阱**：单看一次评估结果会误判 → 改为 base/hybrid 双模式同评估集对比，用差异说话

## 六、20 个面试深挖问题（面试官可能这样问）

### 概念理解
1. **RAG 为什么比"整本书塞进 prompt"好？** → 上下文窗口有限 + 成本 + 时效性；检索只取相关片段，回答有依据
2. **什么是 embedding？** → 文本→语义向量，相似文本距离近；bge-small-zh-v1.5 对比学习训练
3. **向量相似度为什么用余弦？** → 关注方向/语义而非长度；与欧氏的区别
4. **BM25 和向量检索各有什么优缺点？** → BM25：关键词精确、可解释、无训练成本，但不懂同义/语义；向量：懂语义，但依赖模型质量、不可解释

### 设计决策
5. **为什么 300 字/块、50 字重叠？** → 块太大稀释语义、检索粒度粗；太小上下文不完整；重叠兜底切边界
6. **为什么混合权重 0.7:0.3 不是 0.5:0.5？** → 知识库问答以语义为主，关键词为辅；权重可调，当前数据下 0.7:0.3 最优（用评估集试过）
7. **minmax 归一化解决了什么问题？** → 两种分数数量纲不同（余弦 [-1,1] vs BM25 无界），不归一化无法加权
8. **重排为什么用 TF-IDF 字符 n-gram？** → 中文免分词、对术语/代码鲁棒、离线轻量；知道它不如 cross-encoder 但取舍合理
9. **为什么自建评估集？** → 没有适配个人知识库的公开中文评估集；自建才能量化优化
10. **top-k 为什么取 4？** → 经验值 + 评估集验证；候选 20 重排后取 4，平衡信息量与噪声

### 踩坑与修复
11. **你遇到最难的 bug？** → 联网卡死（HuggingFace 下载超时）；解决：离线优先 + 环境检测
12. **评估集怎么避免"过拟合自己的问题"？** → 持续扩充 + 覆盖类型多样 + 不针对已知答案构造问题

### 短板与改进（主动讲）
13. **你这系统最大的局限？** → 固定切分非语义感知、评估集 12 条、无拒答阈值、重排是词面
14. **如果回答完全不在知识库里怎么办？** → 加拒答阈值（正在做）；当前模型可能硬编
15. **并发上来怎么办？** → FastAPI 异步 + 向量库并发读；embedding 模型加载一次复用（单例）；承认当前单机部署
16. **文档格式怎么处理？** → loader 按扩展名分流：txt/md 直接读、pdf/docx 用对应解析库；解析失败跳过并记录

### 延伸
17. **RAG 和微调的区别？** → RAG：知识外挂、可更新、可溯源；微调：改模型行为/风格，成本高不可频繁更新
18. **如何防幻觉？** → 检索质量 + 引用溯源 + 拒答阈值 + prompt 约束"只依据资料回答"
19. **embedding 模型怎么选？** → 中文场景优先中文模型；考虑尺寸/速度/效果平衡；可用 MTEB 中文榜单参考
20. **这个系统还能做什么升级？** → 语义切分 → 跨编码器重排 → 图检索/知识图谱 → 多路召回 → 缓存与流式输出
