# Interview Prep · 4 周冲刺计划（余剑 · AI 应用开发实习）

> 目标：4 周内把 3 个项目挖深 + 算法补核心 + 八股成体系，达到"面试官问什么都有的讲"。
> 原则：**讲深 > 做多**。这 4 周不开新项目、不加新功能，只做两件事：把已有东西挖深一层、把面试要考的东西补齐。

---

## 三、Agent 升级记录（2026-09-29，按抖音 40+ 样本客观差距清单改造）

原 Agent Demo 被客观评估判定为"玩具工具"（数学 add/subtract/multiply + 无记忆 + 无评估）。已升级：

| 差距清单 | 改造 | 文件 | 面试怎么讲 |
|---|---|---|---|
| ① 玩具工具 → 真实工具 | 换成求职场景工具：简历评分 / 岗位质量评估 / JD 关键词抽取（纯规则、可解释） | `agent_resume.py` | "为什么弃用数学工具：那是最典型的'为 Agent 而 Agent'；换成解决真实求职问题、能解释设计" |
| ② 无记忆/多轮 | 短期记忆（最近 N 轮窗口）+ 长期记忆（规则抽取事实表），记忆注入 system prompt | `agent_memory.py` | "短期=窗口滑动防膨胀；长期=事实抽取跨轮保留；超长可压缩" |
| ③ 无评估 | 守卫拦截率 + JSON 提取成功率 + 端到端用例 | `eval_agent.py` | "离线评估 100%（6/6+6/6），端到端 3 条真实用例" |

> 状态：离线评估 100% 通过；端到端 3 条真实用例已复测通过（2026-09-29，新 key 生效后）。

## 四、OfferAgent 学习计划（调整版）

原计划（加功能）→ 调整为（挖深 + 讲深），**不停，只是换方向**：

| 原来想做的 | 调整后 | 为什么 |
|---|---|---|
| 继续加功能（登录、更多页面） | **匹配逻辑结构化打分**：字段抽取 → 维度加权 → 可解释输出（"为什么 Calix 88%"） | 面试深挖的命门：能解释比能跑通值钱 |
| 数字分身更多玩法 | 保持现状，把 6 个能力讲透 | 已是差异化，不必再堆 |
| 界面继续美化 | 停。界面已够好，面试官不看界面 | 时间花在讲深上 |

**OfferAgent 在简历/面试中的定位**：第二项目，主打"产品思维 + 用 AI 解决自己真实问题（自我蒸馏 → 匹配 → 数字分身）"。
**面试深挖重点**（见 `03-offeragent-deep-dive.md`）：
1. 自蒸馏为什么先做"认识自己"再做匹配（差异化设计）
2. 数字分身的合规边界（只答画像内事实，不编造）
3. 话术 v5 的迭代逻辑（v2→v5 每个版本为什么失败，怎么改的）
4. 岗位质量 7 规则的依据（为什么每条规则这么设计）

## 五、关键原则（反复提醒自己）

1. **面试考的是"讲深"，不是"做多"**——OfferAgent 的教训就是反面教材
2. **每个数字都要能解释来源**：83% 怎么算的？88% 怎么来的？答不出 = 编的
3. **主动讲短板**：评估集小、无拒答阈值——"我知道短板在哪、下一步怎么改"比假装完美可信
4. **项目叙述模板**：做了什么 → 关键指标 → 难点/踩坑 → 我的取舍（见 `06`）
