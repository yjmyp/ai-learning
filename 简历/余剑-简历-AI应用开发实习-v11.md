### OfferAgent 求职工作台（独立开发，持续迭代）　2026.09 – 至今

给求职场景做的个人工作台：把「自我画像 → 岗位筛选 → 匹配打分 → 投递话术 → 投递记录 → 面试复盘」做成一条链路，替代手工筛岗和逐条写话术。

把匹配打分从「模型自由给分」改成五维本地加权：同一岗位重复打分标准差 2.36 分 → 0.00 分；22 个真实岗位中自动拦下 8 个不该投的（方向偏算法 5 / 学历要求硕士 2 / 届别不符 1）。

技术栈：Python ｜ DeepSeek API ｜ Streamlit ｜ SQLite ｜ LangGraph ｜ MCP ｜ Chroma / bge 向量检索

- 打分可复算（原方案同一岗位打分会飘）：五维加权——硬技能 0.30 / 项目证据 0.25 / 地点 0.15 / 时间 0.15 / 门槛 0.15，每维输出命中与缺失证据；改之前模型直接给分对同一岗位最大波动 10 分，改之后重复打分标准差 0.00。
- 坏输入不崩（原方案一次非法调用就中断）：10 个工具统一 Schema 注册表 + Plan / Reflect 节点，对 30 类正常与异常输入（非法 JSON / 未知工具 / 缺参 / 类型错 / 非对象 / 大小写与空白变体）做守卫评测，判定 30/30 正确，错误以结构化消息回填后模型自行修正重试。
- 外发可控（投递动作不能交给模型自动执行）：自研 MCP 服务端（stdio + JSON-RPC 2.0，暴露同一套 10 个工具）；执行类工具标注 humanConfirm，投递动作始终由人确认；投递前重访岗位链接拦截失效岗位。
- 链路闭环：15 题自我蒸馏产出结构化画像 → 岗位匹配 → 话术生成 → 半自动投递 → 面试拷问 → 复盘回写画像，用 LangGraph 状态图串起各节点，节点可单独测试。
- 工程化：bge 向量记忆（三档降级保证离线可用）、线程池并发批量打分、调用 trace 落盘与可视化、Token 与成本计量；11 个页面按数据 / AI / UI 三层拆分，离线回归测试 0 失败，CI 覆盖单测 / 服务验收 / 镜像构建。

### RAG 检索问答服务（独立开发）　2026.07 – 2026.08

面向私有资料的检索问答服务：文档入库后按语义检索并带引用回答，检索质量用自建评估集量化，不靠感觉判断好坏。

在 33 篇 / 740 块语料、240 条自建评估集上做两档消融（质量指标两次跑批一致）：混合检索 R@5 93% / MRR 0.796；加多特征重排（默认档）R@5 95% / MRR 0.856。

技术栈：Python ｜ bge-small-zh-v1.5 ｜ Chroma ｜ FastAPI ｜ Streamlit ｜ DeepSeek API

- 重排的收益与代价都用数据说清：同一份 240 条评估集上重排把 R@5 从 93% 提到 95%、MRR 从 0.796 提到 0.856，代价是检索 P95 从约 60ms 升到约 85ms（延迟两次跑批有 ±20ms 波动，质量指标稳定）——因此默认开启重排。
- 可信拒答（避免「词都命中但答案不存在」仍作答）：拒答阈值在评估集上网格搜索校准，再对数值型问题追加答案级自检；库外问题误拒率 2%。
- 链路自研（未套 LangChain 封装）：多格式解析（txt / md / pdf / docx / html / csv / xlsx，其中 xlsx 用 zip + XML 自解析，不依赖第三方库）→ 结构感知切分 → 向量化 → BM25 与向量 RRF 融合召回 → 多特征重排 → 句级引用定位（返回支撑答案的句子与字符偏移）。
- 服务化与运维：FastAPI + SSE 流式 + API Key 鉴权 + 限流 + 存活 / 就绪探针；启动预热把首个请求从 15.3s 降到 62ms；按来源增量重建（改一篇只重算一篇）；trace 计量延迟与单次成本（约 0.0003 元）；单机压测稳态约 20 QPS，Docker 一键启动。
